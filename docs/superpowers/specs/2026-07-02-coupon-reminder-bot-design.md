# 優惠券到期提醒 Telegram 機器人 — 設計文件

日期:2026-07-02
狀態:設計確認中

## 目標

個人用的 Telegram 機器人,協助管理優惠券並在到期前提醒。單一使用者(擁有者本人),
所有優惠券共用一份清單,提醒發送到擁有者的私人對話。

## 使用情境

1. 使用者傳「照片 + 文字說明(`yy.mm.dd 描述`)」→ 機器人存檔並回傳唯一短碼。
2. 每日 00:00 檢查,到期前 **7、3、1 天**及**當天**發送提醒(附原照片),各提醒一次。
3. `/list` — 依到期日由近到遠列出所有優惠券的日期、描述與唯一碼。
4. `/del <唯一碼>` — 刪除指定優惠券。

## 技術方案

- **語言/框架**:Python 3 + `python-telegram-bot` v21(async)。
- **排程**:框架內建 `JobQueue.run_daily`,不需外部 cron。
- **接收模式**:polling(不需公開網址/webhook,適合家用電腦)。
- **儲存**:SQLite 單檔(`coupons.db`)。
- **執行環境**:使用者自己的電腦(長期開機時運作;關機時不運作)。
- **存取控制**:user_id 白名單,只有擁有者可操作,其他人訊息一律忽略。

## 資料結構

### 表 `coupons`

| 欄位 | 型別 | 說明 |
|---|---|---|
| `code` | TEXT PRIMARY KEY | 4 碼英數短碼(如 `a3f9`),隨機產生並確保唯一 |
| `file_id` | TEXT | Telegram 照片 file_id(圖片由 Telegram 保管) |
| `description` | TEXT | 文字描述 |
| `expiry_date` | TEXT | 到期日,格式 `YYYY-MM-DD` |
| `created_at` | TEXT | 建立時間(ISO 8601) |

### 表 `meta`(key-value)

| key | 說明 |
|---|---|
| `chat_id` | 擁有者對話 ID,首次互動時記下,提醒發送至此 |
| `last_check_date` | 最後一次執行每日檢查的日期(`YYYY-MM-DD`),用於同日去重 |

## 行為細節

### 新增優惠券

- 觸發:收到含照片的訊息。
- 解析 caption:
  - 從開頭擷取日期,支援 `yy.mm.dd` 與 `yyyy.mm.dd`(點分隔)。
  - 日期之後的文字為描述(去除前後空白)。
- 成功:產生唯一短碼、寫入 `coupons`,回覆
  `✅ 已新增 `a3f9`,到期日 2026-07-09`。
- 失敗(無 caption、無法解析日期、無描述):回覆格式提示,**不存檔**。
  - 提示範例:`格式錯誤,請附文字說明,例:26.07.09 星巴克買一送一`

### 每日提醒(核心)

- `JobQueue.run_daily` 於每日 **00:00**(本機時區)執行檢查。
- 程式**啟動時**亦檢查一次:若 `last_check_date` 不是今天,則執行今日檢查後更新之
  (當天補發,例:00:00 電腦關機、早上開機即補發今天該發的提醒)。以 `last_check_date` 去重,
  同一天不重複發送。
- 檢查邏輯:對每張券計算 `剩餘天數 = expiry_date − 今天`。
  - 若剩餘天數 ∈ {7, 3, 1, 0} → 發送提醒(附原照片),caption:
    - 7/3/1 天:`⏰ 還有 N 天到期!\n<描述>\n到期日 YYYY-MM-DD\n唯一碼 <code>`
    - 當天(0):`⚠️ 今天到期!\n<描述>\n到期日 YYYY-MM-DD\n唯一碼 <code>`
  - 剩餘天數 < 0(已過期):不提醒,但保留於清單。
- **不做跨日補發**:僅依「今天的剩餘天數」判斷。若電腦連續多天關機而錯過某門檻日,
  該次提醒即漏掉(可接受的取捨,換取邏輯單純)。

### `/list`

- 依 `expiry_date` 由近到遠排序,逐筆輸出。
- 格式(未過期):`📅 YYYY-MM-DD  <描述>  `<code>``
- 格式(已過期):`❌ YYYY-MM-DD (已過期) <描述>  `<code>``
- 無資料:回覆「目前沒有優惠券」。

### `/del <唯一碼>`

- 刪除對應 `code` 的券,回覆 `🗑 已刪除 `a3f9``。
- 查無該碼:回覆「查無此碼:`xxxx`」。

## 設定與啟動

- `BOT_TOKEN`:向 Telegram @BotFather 申請取得。
- `OWNER_ID`:擁有者的 Telegram user_id(白名單)。
- 兩者以環境變數或 `.env` 提供。
- 附:取得 Token、查詢自己 user_id、安裝依賴與啟動的簡短說明。

### 啟動通知

- 程式啟動時,發送一則訊息到擁有者對話(如 `🤖 優惠券提醒機器人已啟動`),
  方便確認 bot 正在運作。
- 邊界:若尚未記錄 `chat_id`(首次執行、擁有者還沒與 bot 互動過),則略過此通知。

## 元件切分

- `db.py`:SQLite 存取(建表、CRUD、meta 讀寫、短碼產生)。
- `parser.py`:caption 解析(日期 + 描述),純函式,易測試。
- `bot.py`:Telegram handler(照片、/list、/del)、白名單過濾、JobQueue 排程與提醒發送、啟動。
- `config.py`:讀取設定。

## 測試策略

- `parser.py`:單元測試各種日期格式與錯誤輸入。
- `db.py`:針對記憶體 SQLite 測 CRUD 與短碼唯一性。
- 提醒判斷邏輯:抽成純函式(給定到期日與今天 → 是否該提醒、訊息內容),單元測試 {7,3,1,0} 與過期情形。

## 明確排除(YAGNI)

- 多使用者/多清單。
- 編輯既有優惠券(改用刪除後重加)。
- 雲端部署、webhook。
- 跨日補發、7/3/1 以外的自訂提醒天數。
